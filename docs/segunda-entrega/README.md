# Segunda entrega: diseño previo a la codificación

Este paquete fija el alcance funcional, las reglas, los datos y la arquitectura objetivo de CONCILIADOR. La codificación del producto y el relevamiento no comenzaron. Los READMEs modulares, CSV, SVG, Compose y SQL son activos documentales; no constituyen una aplicación implementada.

1. [Alcance y módulos](01-alcance-y-modulos.md)
2. [Requerimientos](02-requerimientos.md) y [reglas de negocio](03-reglas-de-negocio.md)
3. [Diseño de base de datos](04-diseno-base-de-datos.md) y [diccionario de datos](05-diccionario-de-datos.md)

7. [Matriz de trazabilidad](08-matriz-trazabilidad.md)

El [glosario](glosario.md) fija el vocabulario común. Los documentos de requerimientos, reglas y diccionario son las fuentes canónicas de sus respectivos detalles; los demás los enlazan sin reproducirlos.

## Límites de la entrega

- Se documenta el MVP académico antes de codificarlo.
- El relevamiento está **No iniciado** y la codificación está **No iniciada**; no se atribuyen entrevistas ni ejecuciones previas.
- Los tiempos de una futura prueba serán observaciones, no compromisos de servicio.
- Las ocho fuentes Mermaid se integran en el documento de diagramas para que GitHub las renderice sin archivos duplicados.
- El entorno local documentado contiene únicamente PostgreSQL 16; los esqueletos backend/frontend son solo READMEs.
